## What this is

**A football predictor that runs as a physical circuit instead of as code.**

Two models are trained in Python, then compiled down into digital logic and loaded onto an
FPGA — a chip whose wiring is reconfigurable, so the model stops being software and becomes
gates. No CPU, no operating system, no inference library at runtime.

You pick an NFL game on a web page. Its 21 features go out over a USB cable, the chip computes
the model in hardware, and a few milliseconds later a win probability and a point spread come
back.

The football accuracy is not the headline. NFL outcomes are close to a coin flip and both
models land at the data's noise floor. What the project demonstrates is the verified path from
`model.fit()` to a bitstream, walked twice with two different model families — a neural network
through hls4ml, a gradient-boosted forest through conifer — sharing one dataset and one locked
feature set.

Both models tie the Vegas opening line on spread (9.76) and neither beats it. That is the
data's noise floor, not a modeling failure — the line already prices in everything these 21
features contain. A 27-config XGBoost sweep lost to it in every config.

The trees win on accuracy, area, DSPs, timing slack and compute latency. Their only loss is
wall-clock round-trip, and that comes from a protocol choice — returning full-width results so
zero-tolerance verification is possible — not from the model.

## The hardware

Around 1,300 lines of hand-written Verilog wrap the generated IP: a UART receiver and
transmitter, a framing FSM that finds packet boundaries and checks an XOR checksum, and a
controller that drives the IP's handshake and encodes the response. The GBDT top chains two
tree IPs through a sigmoid lookup:

```mermaid
flowchart LR
    subgraph BOARD["Basys 3 · Artix-7 XC7A35T · 100 MHz · top_gbdt.v"]
      direction LR
      RX["uart_rx.v"] --> FR["uart_framing_conifer.v<br/>SOF · XOR · watchdog"]
      FR --> CTL["gbdt_controller.v<br/>ap_ctrl_hs ×2"]
      CTL --> W["conifer_win<br/>132 trees"]
      W --> ROM["sigmoid_rom.v<br/>1024 × 12 ROM"]
      ROM --> S["conifer_spread<br/>31 trees + vegas"]
      S --> TX["uart_tx.v"]
    end
    HOST["laptop<br/>pyserial"] -->|"65 B"| RX
    TX -->|"8 B"| HOST
    style W fill:#1a1a2e,color:#fff
    style S fill:#1a1a2e,color:#fff
    style BOARD fill:#0d1728,color:#fff
```

Dark blocks are generated by conifer; everything else is written by hand. The MLP top is the
same skeleton with one hls4ml IP in place of the two trees, fed by a 672-bit AXI-Stream beat
instead of parallel ports.

| Module | Lines | Job |
|---|---:|---|
| `uart_rx.v` / `uart_tx.v` | 94 / 92 | 8N1 at 115200, mid-bit sampling, 2-FF synchronizer. Shared by both tracks. |
| `uart_framing.v` | 194 | SOF hunt, running XOR, NACK on mismatch, ~10 ms inter-byte watchdog |
| `mlp_controller.v` | 167 | Packs 21 bytes into one AXI-Stream beat, drives `ap_ctrl_hs`, saturating encode |
| `uart_framing_conifer.v` | 190 | Same, 65 B in / 8 B out for full-width `ap_fixed<24,12>` words |
| `gbdt_controller.v` | 167 | Chains both IPs, indexes the sigmoid ROM off stage 1's margin |
| `sigmoid_rom.v` | 23 | `$readmemh` of a table generated by the same script that writes the golden |

The controllers carry a 1 ms watchdog that returns status `0x02` rather than hanging. That byte
exists because of the bug below — it turns "the board is dead" into "the model never finished."

## How it works

```mermaid
flowchart LR
    A["🏈 nflreadpy<br/>2000–2024"] --> B["Features<br/>21 vals · .shift(1) guard"]
    B --> C1["Keras MLP<br/>128·64·32 · dual head"]
    B --> C2["XGBoost<br/>stacked win → spread"]
    C1 --> D1["QKeras<br/>8-bit quantize"]
    D1 --> E1["hls4ml + Vitis HLS"]
    C2 --> E2["conifer + Vitis HLS<br/>ap_fixed&lt;24,12&gt;"]
    E1 --> F["Verilog wrapper<br/>UART · controller"]
    E2 --> F
    F --> G["Vivado synth<br/>100 MHz"]
    G --> H["🔌 Basys 3<br/>bit-exact on silicon"]
    style H fill:#76B900,color:#000
    style A fill:#1a1a2e,color:#fff
```

The MLP is a 128→64→32 ReLU trunk feeding two heads. Hidden layers are ReLU-only because ReLU
is one comparator in silicon, and features are MinMax scaled to [0,1] because that drops
straight into an unsigned byte.

The GBDT sends raw features instead — trees split on raw thresholds and `home_elo ≈ 1522` does
not fit in a byte. Its spread head predicts the *residual to the Vegas line*, added back by a
single adder at the end. That reframing is what made it competitive: predicting the raw spread
scored worse than the line itself in all 27 sweep configs, because game margin is nearly linear
in the line and trees approximate a line as a high-variance staircase.

## Three problems worth reading about

**A bug no simulation could see.** The MLP's first IP passed C-simulation and a 50-game
regression, then deadlocked on the board: a sequential FSM around depth-2 FIFOs, a template
doing 512 destructive reads of a 128-entry stream, and one stream with two consumers. The
simulations had passed only because they substituted replay FIFOs that were not in the
bitstream — the tests were patching the bug. Rebuilt on `io_stream` dataflow, with RTL
cosimulation promoted to a mandatory build gate.
→ [AUDIT_REPORT.md](docs/AUDIT_REPORT.md) · [POST_AUDIT_REMEDIATION.md](docs/POST_AUDIT_REMEDIATION.md)

**Zero tolerance, three times over.** Four independent implementations of the GBDT agree
bit-for-bit: the XGBoost/C++ emulation golden, the conifer HLS cosim, XSIM on the synthesized
netlists, and the physical board — identical 24-bit words across 100 games, no tolerance band.
Demanding exactness caught three separate 1-ulp bugs, two before any hardware existed. The
worst: the host encoder read features as float64 while the golden cast to float32 first,
shifting the LSB on 48 of 100 games. Under a tolerance band that ships, and on hardware it
looks like a board that is *mostly* correct and fails half the games for no visible reason.
→ [PHASE6_CONIFER_COMPLETE.md](gbdt/phase6_sim/PHASE6_CONIFER_COMPLETE.md)

**The HLS resource estimate is not a resource estimate.** The MLP's first synthesis came in at
1,917% of the chip — a deprecated pragma silently ignored, putting weights in LUT ROM — and
took seven documented runs to reach 17,888 LUTs. Later, the GBDT's csynth estimated
96,878 + 33,369 LUTs, implying neither stage could ever fit. Real Vivado synthesis:
6,758 + 5,111. Inflated 14× and 6.5×.
→ [REDUCE_LUT.md](docs/REDUCE_LUT.md)

One nice consequence of all this being verified: you can see the tree structure from outside the
chip. Sweeping `elo_diff` with every other feature pinned produces a staircase rather than a
ramp — 8 discrete levels with flat plateaus, which is the depth-2 split structure made visible.
It is also monotonic, so the training-time monotone constraint survived XGBoost → conifer → HLS
→ fixed-point → silicon intact. The MLP's equivalent sweep moves smoothly. Neither curve could
come from a lookup table.

## Reproduce it

**Check the numbers without installing anything.** Every headline figure is committed as JSON:

```bash
cat artifacts/mlp/synthesis_report.json   # 17,888 LUT (86%), 18 DSP, WNS +0.126 ns
cat artifacts/gbdt/gbdt_report.json       # val 65.7% / AUC 0.716 / spread MAE 9.757
cat artifacts/mlp/quantization_report.json
```

**Rerun the software half.** Fully reproducible on any machine with Python 3.12:

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python phase1_data/pipeline.py           # nflreadpy → data/processed/games.parquet
python mlp/phase2_model/train.py         # → artifacts/mlp/model_best.keras
python gbdt/phase2_train/train_gbdt.py   # → artifacts/gbdt/*.json
pytest tests/ -v
```

The trained artifacts are committed and are the source of truth, so the training steps are
optional — the tests run against what is in the repo either way. Board tests are gated behind
`FPGA_PORT` and skip without hardware attached. The GBDT trainer keeps the test set sealed
until validation clears both gates: 63% win accuracy, and a spread MAE that ties the Vegas
line. Miss either and it prints what it missed and stops before touching test.

**Build the hardware.** You need a Basys 3, Vivado / Vitis HLS 2025.2 (free WebPACK is enough),
and you will have to fix a few absolute paths. Synthesis, programming, the two UART protocols
and the board-verification scripts are all in **[docs/BUILD.md](docs/BUILD.md)**.

## Limitations

- **Prediction quality is modest by design.** ~65% accuracy and 9.7 pt MAE is near the ceiling
  for schedule-level features. This is a systems project, not a betting edge.
- **The GBDT's fixed-point path disagrees with float XGBoost on 0.7% of games** (4 of 543),
  from conifer's threshold-rounding convention. Not fixable by widening the bit width,
  accepted, and invisible to the golden-based verification — but real.
- **The bitstream is volatile.** Reprogram after every power cycle.
- **Board tests need hardware** and so cannot run in CI.
- **Not clone-and-go for hardware.** The software half is; the bitstream you build yourself.
